Why it happens

Arena only counts PRs merged into develop or a hotfix branch, and PRs into main are excluded. Admin and Nexus have no develop branch - their work goes straight to main. The audit view labels these PRs excluded rather than missing, so the gap never shows up as a problem.

Where the scoring bends

Beyond coverage, a few rules reward the wrong things - real examples from this week.

Repeat-edit decay
4,022 XP

lost to decay this week. Each further touch of the same file is worth 0.5x, down to 0.1x - and that includes deleting lines, so iterative refactors and cleanups lose out.

AI-dump rule
-60 XP

One PR flagged this week (about 6,000 lines merged 2 minutes after opening). The penalty only touches the 100 merge XP, so it barely registers - and it counts deletions as churn.

Slop rule
0 PRs

None this week, but over 500 production lines in 2 files or fewer with no tests halves XP - deletions included, so a big cleanup in a couple of files gets halved.

Rules page vs actual scoring
  • Says merge XP is a churn-weighted average across file types - it actually uses the dominant type.
  • Never states the 1 vs 3 XP per added / deleted line.
  • Lists an "other" file category that nothing can fall into.
Also worth knowing
  • No cap on lines per PR - one PR earned 10,735 XP, 39% of the week.
  • Only package-lock.json is down-weighted; other lockfiles and generated files count as full production.
  • Renames and moves earn only the 100 merge XP - GitHub reports 0 lines.

What it means and what to tune

Arena is a solid base - the scoring just needs tuning so the board reflects all the real work, not only what lands in develop.

Coverage is the big one

Branch rules decide more than effort does: 17 of 30 PRs and 32% of changed lines this week never reached the board.

Size beats substance

With no cap and deletions at 3x, two PRs took 55% of the week's XP.

Refactors are short-changed

Decay on deletions, slop/AI-dump counting deletions and near-zero XP for renames all push against cleanup work.

10 suggested fixes - and the expected effect
  1. Count PRs into each repo's default branch (or per-repo allowed branches)Admin, Nexus, Marketing and Infra PRs into main count: 13 → 26 of 30 PRs this week, +8,436 XP on the board
  2. Optional org-wide repo discoveryNew repos are picked up automatically - no silent gaps like Admin and Nexus
  3. Base the slop and AI-dump rules on additions onlyLarge cleanups stop being treated as dumps (no PR affected this week)
  4. Give renames / moves a flat XPRestructuring earns more than the bare 100 merge XP (none this week)
  5. Exempt deletions from repeat-edit decayIterative cleanup keeps its value: +1,914 XP this week
  6. Cap lines per PR (2,000 weighted lines used here)Largest PR 10,735 → 2,952 XP; top share 55% → 23%
  7. Down-weight all lockfiles and generated filesGenerated code stops counting as production work (no PR affected this week)
  8. Make Insights repo-agnosticInsights shows every counted repo, not just UI vs API
  9. Correct the Rules pageEveryone can see how XP is actually earned
  10. Optionally pick up direct pushes to default branchesWork that skips PRs becomes visible, labelled separately
Method and assumptions
  • All 36 PRs merged Thu 22 Oct 00:00 to Mon 26 Oct 2026 SAST across the Genesis repos, read from GitHub (author, branch, times, lines and files).
  • Current applies Arena's scoring as coded with its default settings: 100 / 1 / 3 XP, file weights, task-link and hotfix bonuses, repeat-edit decay, AI-dump and slop rules.
  • Revised applies the fixes above, with a cap of 2,000 weighted lines per PR and 5 XP per pure rename. Deletions stay at 3x - that weighting is left as is.
  • Repeat-edit history is seeded from PRs merged since 1 Sep 2026. 6 PRs from an automation account are excluded, as Arena does. Direct pushes are not included.
  • Repo lists and setting overrides stored inside Admin were not visible, so live numbers may differ.
